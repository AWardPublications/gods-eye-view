# ADR-001: Open-Source Voice & Speech Architecture Adoption

**STATUS**: ACCEPTED  
**DATE**: 01 September 2026  
**DECISION-MAKERS**: Antigravity Systems Engineer & Speech Architecture Team  

---

## 1. Context and Problem Statement

Alex Wenger² requires a real-time, governed **DATA → TEXT → VOICE → PLAYER** capability.
The canonical response text generated by the DNSL / Article 19 engine is authoritative.
The speech engine must render governed text into natural, tone-modulated audio with strict latency bounds (< 200ms) without cloud vendor lock-in or proprietary licensing traps.

---

## 2. Considered Alternatives

1. **Stack A (Proprietary Cloud API)**: OpenAI Realtime / ElevenLabs API.
   * *Rejected*: High cost per minute, non-zero risk of external service downtime, breaks self-hosted offline guarantee, sends un-anonymized audio to external third-parties.
2. **Stack B (Classical Open-Source)**: Coqui TTS + Vosk + WebRTC.
   * *Rejected*: Coqui project is unmaintained/archived, high CPU usage, older acoustic models.
3. **Stack C (Pluggable ONNX Multi-Engine — SELECTED)**:
   * **VAD**: Silero VAD v5 (MIT)
   * **STT**: Sherpa-ONNX + Moonshine/Whisper-ONNX (Apache 2.0 / MIT)
   * **TTS Primary**: Kokoro-82M ONNX (Apache 2.0)
   * **TTS Fallback**: Piper ONNX (MIT)
   * **Browser Fallback**: Web Speech API (`SpeechRecognition` / `speechSynthesis`)
   * **Transport**: Opus over WebRTC DataChannel / Streaming Ring Buffer

---

## 3. Decision Drivers & Why the Winning Stack Won

1. **Licensing Freedom**: 100% Apache 2.0 and MIT permissive licenses. Zero commercial restrictions.
2. **Deterministic CPU Performance**: Kokoro-82M and Piper achieve Real-Time Factors (RTF) < 0.15 on standard 4-core CPUs without requiring dedicated GPUs.
3. **Phoneme-Level Tone Controllability**: Kokoro and Piper support direct prosody parameter scaling (speed, pitch, style weight) mapped directly to Article 19 Tone States (`BASELINE`, `MODULATED`, `DECAYED`, `RECOVERING`).
4. **Resilient Fallback Tier**: If a local ONNX engine fails, the system automatically falls back to Piper or native Web Speech API without dropping the coaching turn.
5. **Zero Data Leakage**: All inference runs locally in-process or in-browser; no player audio is transmitted to external servers.

---

## 4. Swappability & Evolution

All voice engines are abstracted behind the `src/voice/contracts/` interface:
* `SpeechToTextProvider`
* `TextToSpeechProvider`
* `VoiceActivityDetector`
* `AudioTransport`

If a new, superior open-source speech model emerges in the future, it can be integrated by writing a single adapter in `src/voice/adapters/` without altering the Article 19 intelligence or DNSL governance layers.
